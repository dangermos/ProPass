# Pro Express — detection, SKU recognition, training, and open-source research

Research checked 2 October 2026. Public documentation and code inspection support model capabilities and licenses. All training budgets, configuration choices, thresholds, and project performance goals below are engineering estimates, not measured results on this user's hardware.

## Recommendation and why

Train a small **one-class merchandise detector from `yolo26n.pt`**, then identify each crop with a separately fine-tuned **torchvision EfficientNet-B0, `EfficientNet_B0_Weights.IMAGENET1K_V1`**, predicting the 5–10 enrolled SKUs. Start with 8 SKUs, including two confusing variants and two physical copies of at least two SKUs. Maintain physical identity using the tracker plus a canonical object ledger; aggregate SKU evidence per canonical object. The SKU classifier must never determine whether two observations are the same physical instance.

Why separate stages: a generic detector can keep tracking when packaging text is obscured; the crop classifier receives far more effective product pixels than the detector's classification head; adding catalog entries and measuring identification errors are separate from localization. Still run a direct 8-SKU detector as an ablation: it is a legitimate simpler contender, and may win on this fixed small catalog. A one-class detector is not an open-world guarantee: unfamiliar merchandise may be missed, so unknown-product detection requires explicit testing and confirmation fallback.

Frozen DINOv2 ViT-S/14 (`dinov2_vits14`) with a multi-view image gallery is a meaningful baseline. Train a linear head on cached 384-dimensional embeddings before trying end-to-end foundation-model fine-tuning. It can show whether the classifier training adds value. With 8–20 SKUs and 20 reference views each, a normalized matrix multiply is enough; FAISS is unnecessary until catalog/gallery size warrants indexing.

The core contribution is **uncertainty-aware temporal inference and experimentally demonstrated counting reliability**, not the number of model names or services in the repository.

## Competing vision architectures before convergence

| Candidate | Strength | Failure mode | Training/data | Time estimate |
|---|---|---|---|---|
| Direct SKU detector + tracker | Small fixed catalog; one inference pass | Class flips fragment class-aware tracks; small text insufficient | SKU-labeled boxes; detector fine-tune | 1–3 days |
| Merchandise detector → crop classifier + object ledger | Separates counting/localization from identity; high crop resolution | Crop classifier needs unknown rejection and partial-view testing | Boxes + SKU crops; detector and lightweight classifier | 2–3 days with disciplined scope |
| Detector → visual gallery retrieval | Fast onboarding; explainable nearest examples | Gallery/view domain gap; near-identical packaging | Few multi-view reference images; linear probe optional | 1–3 days |
| Barcode-first video portal + temporal counting | Exact identifier when code visible | Code usually hidden/blurred; does not solve instance identity | Barcode catalog; no vision training | 1–2 days |
| Text/exemplar segmentation tracker (SAM3.1) + crop retrieval | Tracks masks, can use concepts/exemplars | Gated assets, resource/setup complexity, segmentation IDs not transaction identity | Prompt exemplars; optional mask data | Several days–week |
| Hand/person/product graph + interaction classifier | Models owner and take/return causality | Needs scarce labeled temporal interactions, fails under overlap | Person/hands/product boxes, transfer/event labels | 1–3 weeks |
| Two-camera portal + cross-view fusion | Resolves visibility ambiguity, impressive geometry | Synchronization/calibration, cross-view correspondence | Paired views, calibration, identity annotations | 1–2 weeks |
| Cart-mouth event camera + weight change | Observable add/remove boundary, strong sensing | Handheld exits unhandled; integration/calibration | Cart-mouth videos + sensor stream | 3–7 days |

For a fast portfolio MVP rank the separated detector/classifier + ledger first; direct detector second; retrieval third; barcode-first fourth. For extended robustness, two-camera fusion outranks increasing model size. For ambitious CV research, the interaction graph has depth but is a bad first three-day target. Barcode/OCR are valuable complementary evidence, not substitutes for instance tracking.

## Exact SKU recognition: concrete behavior

1. Pad box by 5–10%, clip to original 1080p frame, crop original image rather than resized detector tensor. Preserve aspect ratio; resize/pad classifier crop to 224×224 initially. If confusing text is physically tiny, acquire a closer/sharper view; resizing cannot recover it.
2. Evaluate classifier on clear crops at 3–5 Hz per active object, not every identical frame. Score crop quality using minimum dimensions, motion blur, occlusion estimate, and boundary truncation. Maintain best 5–10 crops with timestamps.
3. Aggregate quality-weighted logits/probabilities over separated views. Correlated neighboring frames are not independent evidence; cap contribution from a brief view burst. Train-time crop jitter should mimic detector imperfect boxes.
4. Apply calibrated confidence and top-1/top-2 margin threshold chosen on validation data. Initially require agreement on ≥3 useful observations separated across ≥0.3 seconds; treat these as tunable heuristics, not certainty. `UNKNOWN`/`REVIEW_REQUIRED` is a valid output. A softmax maximum by itself is not reliable open-set rejection.
5. Compare DINOv2 gallery similarities and classifier predictions; disagreement triggers review. Avoid adding two models permanently unless ablation shows better transaction accuracy at acceptable latency.
6. If a UPC/EAN is readable, check checksum and catalog mapping. Assign read only to containing object with unambiguous overlap; neighboring codes must not overwrite its SKU. UPC can override weak visual evidence but conflicting strong evidence should trigger review, not silently overwrite. Two boxes with same UPC are two instances if separately tracked.
7. OCR on selected sharp crops can recognize distinguishing model number, pack size, voltage, or dimensions; use exact/fuzzy matching against local catalog fields. Logo recognition gives brand evidence, not exact SKU. Feature matching is useful for textured rigid packages under small viewpoint changes; brittle on reflection/rotation/occlusion.
8. When a SKU changes after provisional addition, update evidence and mark cart reconciliation needed. Persist original prediction, new prediction, and reasons in the audit stream. Never increment quantity because a label changed.

Two perfectly identical copies can share SKU and embeddings. Neither classifier nor SKU embeddings can recover which physical copy emerged from complete overlap. Motion continuity, extra view, constrained handling, or abstention is necessary. Fully hidden quantity is unobservable to a single RGB camera.

## Training recipe

Collect own eight-SKU data first. Begin with 24–40 staged clips of 15–30 seconds plus 20–30 clean reference photos per SKU; extend to 60–100 clips for proper failures. Sample 600–1,200 useful nonadjacent frames (not thousands of duplicates) with all visible merchandise boxes; aim for 150–300 varied crops/SKU, 1,200–2,400 total. Include empty scenes, hands without products, tools belonging to scene, unknown products, hard negatives, two identical copies, and partially visible known products. Unknowns can be detected as merchandise while classification is rejected. Separate unknown SKUs used for threshold validation from unknown SKUs used for final testing.

Split **by whole clip/session before extracting frames or augmenting**, roughly 60/20/20. Hold out actor, lighting session, background, and object physical copy where possible, while ensuring all enrolled SKUs have training examples. Reference gallery must use only training material. Test from a later recording session. Publish split manifest and specimen/video IDs. Random per-frame splitting gives inflated performance.

Detector labels: `merchandise` bounding box; additionally store SKU, `physical_instance_id`, visible fraction/truncation, session and clip metadata for classifier/evaluation. Annotate visible merchandise consistently; do not draw imaginary boxes for fully hidden objects. A packet/toolbox/retail multipack is one sale unit according to catalog, not each component inside.

Detector procedure: first run 5 epochs to validate labels and throughput; then `yolo26n.pt`, image 640, batch 16 on 12 GB card or 8 on 8 GB card, up to 60 epochs, patience 12, AMP enabled, AdamW learning rate 1e-3, weight decay 5e-4, cosine schedule and 3 warmup epochs. Fix seed and explicitly set optimizer; current Ultralytics `optimizer=auto` can ignore manual learning rate. Tune thresholds separately from weights. Use modest rotation (~±15°), brightness, scale and translation, crop/occlusion augmentation matching reality. Disable vertical flipping; use horizontal flipping only if validation confirms it does not corrupt discriminative text evidence. Start mosaic at 0.2 and disable last 10 epochs; avoid aggressive copy-paste producing impossible overlaps. Generic detection can tolerate transformations the exact-text classifier cannot. If small-item recall is weak, improve framing then try 960 with reduced batch, or yolo26s, not both without attribution of improvement.

Classifier procedure: EfficientNet-B0 ImageNet checkpoint, 224 crop; replace head with 8 outputs. Freeze feature extractor for 3–5 epochs, head AdamW 1e-3; then unfreeze final feature blocks for 10–20 epochs, backbone learning rate 1e-4 and head 3e-4, weight decay 1e-4, early stop on validation loss/macro accuracy with patience 5. Freeze BatchNorm running statistics during small-data fine-tuning; do not silently refit them on tiny batches. Label smoothing 0.05 is optional and must be tested against sharp rejection thresholds. AMP, batch 32 initially. Use modest crop jitter preserving product, ±10° rotation, mild color variation, blur, exposure and synthetic hand-like occlusion. No MixUp/CutMix initially for exact packaging text; add only if ablation helps. Save best checkpoint, label-index mapping and calibrated temperature. For confusing packaging try 320 classifier crops and/or OCR.

DINOv2 baseline: create multi-view gallery; extract frozen vits14 embeddings at its supported processing size (e.g. 224, divisible by 14), L2-normalize. Fit linear classifier to cached features with cross-entropy, AdamW 1e-3, 20–50 short epochs early-stopped; cosine nearest-neighbor retrieval gives another baseline without training. Metric learning/Siamese training is appropriate later only when there are enough view/instance pairs and hard negatives; an 8-SKU classifier often provides better return on annotation time.

Training priority: detector domain adaptation first, light crop classifier second, calibrated unknown rejection and temporal aggregation third. Wasteful in MVP: training from scratch, training CLIP/DINO backbone on tiny data, training tracker Kalman filters as if learned weights, retraining generic person ReID for product identity, full SAM fine-tuning without evidence mask quality is bottleneck, giant detector ensembles, and neural event models with tens of clips. Track association and event logic should first be deterministic, testable code.

## Hardware and realistic budgets

NVIDIA official specs list RTX 4070 Super **12 GB** and non-Ti desktop RTX 4060 **8 GB**. Verify actual cards before setting batches. These estimates assume small dataset, SSD, modern CUDA/PyTorch, AMP and no concurrent large GPU job. They are planning ranges, not benchmark promises.

| Job | 4070 Super estimate | 4060 estimate | Starting memory/batch |
|---|---|---|---|
| YOLO26n, 600–1,200 images, 640, 40–60 epochs | 20–90 min | 35–150 min | 4–8 GB at batch16; 3–6 GB batch8 |
| YOLO26s or 960 detector ablation | 45–180 min | 1–4 hours | batch8 at640 or batch4 at960; ~6–11 GB on 4070S; reduce batch if OOM |
| EfficientNet-B0, 1,200–2,400 crops, 224, 15–25 epochs | 5–30 min | 10–45 min | ~2–5 GB, batch32–64; start32 |
| DINOv2 frozen gallery extraction + linear head | Several minutes–20 min | Several minutes–30 min | 2–5 GB extracting batches; cached-head training can use CPU |
| RF-DETR small detector experiment | ~1–4 hours | ~2–6 hours | batch2–4 and gradient accumulation; profile first |

Use the 4070 Super for detector, the 4060 independently for classifier or gallery evaluation; alternatively leave 4060 running application inference while detector trains. Do not pool VRAM or presume heterogeneous DDP is beneficial. Measure 100 training steps and peak memory to replace estimates. If each epoch takes `t`, approximate remaining time from measured `t×remaining epochs`, including validation. Data quality/annotation (roughly 3–8 hours to label/correct 600–1,200 frames with assistive propagation, highly variable) is likely more limiting than training time.

Inference planning target: process 1080p input at 10–20 detector updates/s, render video at 30 fps, classify 3–5 Hz per object. Initially budget 10–30 ms for small detector GPU inference and 5–20 ms for a small crop batch, then measure end-to-end decode/resize/queue/inference/tracker/database/WebSocket delay. No vendor T4/A100 or isolated network speed should be reported as measured application performance. Aim for p95 evidence-to-cart update <250 ms as a target; report observed p50/p95 and dropped frames. If overload occurs, bounded latest-frame queue and explicit frame timestamps matter more than displaying every frame.

Specs sources: [NVIDIA 4070 family](https://www.nvidia.com/en-us/geforce/graphics-cards/40-series/rtx-4070-family/), [NVIDIA 4060 guide](https://www.nvidia.com/en-us/geforce/news/ultimate-guide-to-4060/). Training arguments and optimizer behavior: [Ultralytics training docs](https://docs.ultralytics.com/modes/train/). Classifier family: [torchvision EfficientNet-B0 documentation](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.efficientnet_b0.html).

## Validation and portfolio experiments

Detection: merchandise recall/precision in checkout ROI; mAP50 and mAP50:95; recall by occlusion, product size and SKU. Exact recognition: macro top-1 accuracy, per-SKU confusion matrix, rejection false-accept rate on unseen products, accepted-prediction accuracy versus coverage, temperature-calibrated reliability plot. Separate crop-oracle evaluation from actual detector crop evaluation.

Tracking: ID switches, fragmentation, IDF1/HOTA on annotated sequences; canonical duplicate/merge errors. Physical quantity: per-SKU absolute count error and exact final-cart match rate. Events: add/remove precision/recall, incorrect duplicate additions, missed removals, event latency. Transactions: all cart SKUs/quantities exactly correct is the principal success metric; good mAP does not imply good checkout.

Compare: frozen detector vs fine-tuned; direct SKU detector vs generic detector + classifier; single-frame classifier vs temporal aggregation; classifier vs DINOv2 retrieval; raw track IDs vs canonical ledger; barcode/OCR off/on. Keep fixed held-out session for fair comparisons. Obtain all resume metrics experimentally and include test count and scope.
